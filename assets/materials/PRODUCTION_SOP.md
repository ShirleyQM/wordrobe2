# 服装美术生产 SOP

本项目只用一套人物母版、一套主界面和一套素材库。本文件是所有新出图、基础款、重做任务的共同规范；批次清单补充款式，不另定人物版本。

### 人物底图与脸部分层（2026-10-25）

运行时身体使用 `characters/clean-body-v4/body-{0|1}-{0|1}.png`，来源是确认过的去肩带、低罩杯底图 `outputs/body-remaster-v4/strapless-preview.png`，939×1676 归位，保留肤色打底。四个状态目前共用同一张有打底的身体，不能宣称它已经实现无生理细节人台的遮挡层自动移除。旧 `low-coverage-v3` 的修补皮肤及 `separated-body-v1/body-*` 不再作为运行时身体。脸部独立叠加 `separated-body-v1/heads/<face-id>.png`；裁缝铺也必须加载此脸层。原母图、服装和发型手调数据保留。头部来源仍可由 `tools/build-separated-character.cjs` 重建，不能用该脚本覆盖当前身体来源。

## 最高优先级：所有服装都不画内片（2026-10-24）

用户最新要求是“都不要画内片”。适用于贴身款、宽松款、外套、上衣、裤子、半裙、连衣裙及配件，不只是之前点名的几件。

- 只画正面实际看得到的衣料。后领圈、后腰边、袖口/裤口内筒、后翻片、里衬、衣摆背面、外套开襟内的背部连接片，全部不画、不补、不恢复。
- 只制作衣服，不给人物身体边缘重新勾线；人物沿用原版的勾线。
- `front.png` 是正面可见衣料；`back.png` 一律为同画布全透明技术占位。禁止把多余内片移到 back 层。
- 正面翻领、前门襟、正面褶皱及其阴影仍可画，它们不是内片；但不能借“立体感”画出开口后缘、空筒或背后的衣料。
- 独立内搭属于另一件装备，与“衣服内片”不同。用户要求内搭时单独制作、单独穿脱；未要求时不擅自补。纱、蕾丝的透孔不能烘焙肤色、内衬或另一件衣服来填满。
- 已删除的内片不能在重新生成、补全、换色、面料替换、分层或微调保存时重新出现。本规范更新不代表历史库存已经逐件返修通过。
- 肩带顶端顺着肩颈的斜坡结束：靠颈侧高、靠肩外侧低，只留贴合肩线的正面薄边。不能平头悬在锁骨下，也不露顶部后片、翻折帽或背面带唇。前段不足时在已定肩带轮廓内补画真实面料，不能复制拉长旧像素或沿人物 alpha 扩边。
- 内衣是贴身内搭：按用户最新保存的姿态与服装轮廓绘制，杯侧、下围和衣身贴合，不做垂坠丝带、悬挂装饰或自由飘出的布片。高清返修须同时交付真正重画的高清面料和运行时高清穿戴图，不能只把约 230 像素宽的旧衣料放大；网格、曲线、位置、缩放、擦除、印花与备注继续保留。
- 穿长裙时检查裙摆至脚踝的身体连续性。旧 `bodyOcclusionRects` 不得越过实际裙摆遮掉可见小腿；必要的裙侧身体遮挡要保留，遮挡下边界应藏在经检查的实布区域内，不直接套用另一条裙子的矩形。`dress-emerald` / `dress-noir-lace` 曾因旧遮挡延伸到 y=1430 出现断腿，已收至裙身内 y=1340，详见 `sources/dress-calf-gap-investigation-v1/`。身体遮挡配置属于运行时元数据，修改后须实际刷新与试穿；不靠补身体像素或改裙长掩盖。

## 一、先分类，再定轮廓

每件同时记录下面三个维度，不能用“上衣”一个标签代替全部制作要求。

1. **装备槽位**：`top` 上衣、`coat` 外套、`bottom` 下装、`dress` 连衣裙、`jewelry` 配件。腰间系衣、外挂裙片放配件；皮带、帽子、袖套按独立配件制作；包包不做。
2. **版型**：贴身、常规、宽松。它决定肩胸腰胯的松量与衣料包覆范围；不能从人物 alpha 自动生成。
3. **袖型与材质**：无袖/短袖/常规长袖/宽袖/灯笼袖/喇叭袖，以及针织、梭织、皮革、麂皮、纱、蕾丝等。宽袖可以配贴身衣身，不能把两者当成互斥分类。

批次 `item.json` 可另存 `production` 描述用于制作记录；这些字段不自动成为前端功能：

```json
{
  "id": "example-knit-v1",
  "slot": "top",
  "production": {
    "fit": "fitted",
    "sleeve": "wide",
    "fabric": "knit",
    "innerPieces": false,
    "canvas": [939, 1676]
  }
}
```

### 1. 贴身上衣：T 恤、衬衫、针织衫、抹胸

- 先对齐肩点、腋点、胸线、腰线，再检查领深和衣长。贴身仍要有合理衣料松量，不把身体轮廓复制成衣服。
- 有袖款先保证袖根和衣身连续；腋下不能断开，也不能画成贴在皮肤旁的一条细带。胸侧、腰侧要有实际布面，不用肤色/纯色补丁填缝。
- 贴身袖顺着固定张臂姿势，检查上臂、肘部和手腕。袖长在正面袖口结束，不向下拉出模糊尾巴。
- 无袖款检查肩带、腋下开口和胸侧覆盖；抹胸检查上缘、胸侧及下摆。不能为遮母版内衣而重画身体，需在本件已确认的衣服轮廓内解决覆盖。
- 衬衫领只保留前领与前门襟，领口后方透明。褶皱支持结构但不过密，胸前保留可用的印花区域。

### 2. 宽袖上衣：宽袖、灯笼袖、喇叭袖

- **先画完整宽袖轮廓，再画材质**。这批按用户要求袖子更宽、内缘更靠近身体；靠衣服的袖面增宽实现，不沿人物 alpha 扩边。
- 先定肩/落肩、腋下连接、肘部、袖口四处。袖内缘向衣身靠近但仍保持设计需要的透明间隙；不能把手臂与身体之间整块填成布。
- 袖根与身体相接处要有完整结构，不能只让两个轮廓擦边相碰。左右袖都按固定姿势绘制，不能直接镜像照片中一边的垂手袖。
- 宽度增加的整片袖面必须有同种针脚、格纹、绒感与褶皱，不能出现无纹理长条。灯笼袖有收口；喇叭袖向前缘展开，但都不画袖口后缘和内筒。
- 检查手腕与手掌遮挡，袖口不可无意遮住整只手。袖摆跨到衣身前方时用实际前片关系处理，不增画身体后的布片。

#### 正面袖口浅内弧（2026-10-24 用户补充）

- 用户允许对生硬平直的袖口，定位正面两端后用局部蒙版修浅内弧，并在前缘布面上加轻微阴影。这里的内弧是正面切口曲线，仍然禁止内片、后缘、内筒和椭圆衬里。
- 可复用 `tools/soften-cuffs.py`：每袖显式设置端点、向袖身的法线、弧深与阴影强度。只做局部裁减与布面压暗，不扩大 alpha、不补颜色、不拉伸衣服。需要先确定真实袖口，不能把手腕固定坐标套给所有款。
- 弧深随实际袖宽控制，平直宽袖先用浅弧；蕾丝花边、纱边、灯笼袖口、已经有自然起伏的袖口不能统一硬切。缺布或结构有误时仍须 image_gen 补画，不适用此工具。
- 有手调时把局部裁减/阴影蒙版经已有用户网格映射到已保存穿戴图，不重置用户曲线。源图、保存图、缩略图与实际衣橱一起验收。首批记录在 `sources/cuff-arc-v1/`，不代表全部库存已处理。

### 3. 外套：茧型、夹克、大衣、开衫

- 外套有自己的服装轮廓。先确认肩宽、袖肥、衣身松量、下摆与开襟，再在这个轮廓里画。茧型的外鼓与收摆属于设计，不按身材强行收紧。
- 开襟中间按设计保持透明，能看到当前人物或另选内搭；不画连接左右前襟的后领、后背或内衬横片。
- 翻领、口袋、扣件画在可见前片上。袖口只画前缘，开襟边缘不能露出额外里衬长条。
- 皮衣用连续皮面、接缝、受力褶皱和克制反光表现质感；麂皮用细绒与柔和明暗；毛外套保留可辨纤维。都不能靠全局模糊制造柔软感。
- 同时试穿一件薄内搭、一件下装，确认衣身两侧、腋下和开襟没有露肤裂缝或错误遮挡。

### 4. 半裙：直筒、A 字、百褶、荷叶、长纱裙

- 先锚定前腰中心、腰宽、胯宽和裙长；上沿只保留前腰头，不画后腰弧线、内侧椭圆和后片。
- 腰胯包覆不足时重画真实裙片；不能仅扩大腰头色条。与短上衣、塞衣下摆分别试穿，避免腰侧缺口。
- 百褶、叠片、荷叶边可画正面叠压及阴影，但不能露出裙摆背面或额外内衬。长裙检查两侧边缘、手部遮挡、下摆是否被画布截断。
- 纱裙与蕾丝裙分清实布、纱面和透孔；透孔保留真实 alpha。不能用灰雾、肤色或棋盘格模拟透明。
- 只用于叠穿的腰间裙片归配件，不能和裤子烘焙成同一件，也不要自动替用户卸掉裤子。

### 5. 裤子与短裤

- 先对前腰、胯、裆点，再对膝部、脚踝/裤脚。两条裤腿各有真实布面，裆部连接自然，腿间保留正确负形。
- 阔腿靠整段裤腿轮廓和布量表现，喇叭裤从膝附近展开；不能只横向拉宽图片或沿人物腿补色。
- 前腰与裤口都只画前面，不画后腰边、裤管内筒和裤脚后翻片。口袋、门襟、明线是正面细节，可以保留。
- 牛仔纹理要沿腰胯与裤腿连续；短裤检查大腿外侧、裆部和前裤口。长裤检查脚尖遮挡，不能改变人物腿脚位置。

### 6. 连衣裙与配件

- 连衣裙按真实款式建立版型族：披风大袖蓬裙、挂脖 A 字裙、露肩短裙、露肩长袖鱼尾拖尾分别锁轮廓；不能为了复用把参考图一律改成吊带长裙。先核对领口、袖型、腰位、裙量和拖尾，再生成材质。相近轮廓内才复用印花、换料与局部挖洞；改变袖型、裙量或拖尾时另建服装轮廓。
- 连衣裙同时通过上装和下装要求，不能只对齐整体包围盒；肩/腋/胸/腰/胯/裙长都要逐项看。抹胸、吊带、宽袖分别套用对应要求。
- 帽子对齐当前头部与盘发，帽檐不挡眼；只画正面可见帽体，不补帽子内腔。皮带贴合前腰；系腰衣保留前面结与垂片，不补身体后的环绕片。
- 配件必须能单独穿脱。当前桌面端皮带、系腰衣、袖套用 `accessoryType: belt / waistwrap / armwarmers` 区分；帽子用 `cap`。不要为新类别擅自复制另一套装备系统。

## 二、共用工序与每一步的产物

### A. 去重、读手调、锁轮廓

- 查看当前衣橱、基础款标签、已有 ID 与最新拟合数据。同款不同配色复用换色；参考照片只取设计方向，不完全照抄，不带品牌字样。
- 打开当前人物母版；把衣服轮廓画成独立遮罩，按类别确认锚点。已有手调作为约束保留。不得从身体 alpha 扩出“衣服轮廓”，也不能把被旧扩边污染的 alpha 标为批准轮廓。
- 输出 `outline.png`、`outline-record.json`、设计记录与出图前的拟合快照。纯遮罩使用 L 灰度，或用 RGBA 的 alpha 表示覆盖；不要使用不带 alpha 的 RGB 黑白图冒充 RGBA 遮罩。

### B. 在衣服轮廓内绘图

- 用 image_gen 画真实面料、接缝、褶皱，参考当前姿势、服装轮廓与设计图。要求真实透明背景、只有衣服、所有内片禁止、高清细节。
- 针织需看见针脚/罗纹/纤维变化；纱需有薄层透光、柔褶、真实透明；蕾丝需有实线与透孔；格纹与提花不能在袖内侧突然消失。
- 高清可以用 2 倍画布绘制，最终统一到 939×1676；单纯放大不算增加细节。原始生成图、实际提示词及所有补画图归档。
- 缺布、腋下断接、袖内缘异常时回到这一阶段补画。不能让程序替美术画出一块颜色近似的衣片。

### C. 等比归位与透明合成

- 已有同画布归位图直接使用；新图只允许初始等比缩放与平移。先按类别锚点计算，再实际试穿，不用整个图的中心或边框自动猜身体位置。
- Pillow 合成的关键示例（输入为已定位 RGBA 与批准的衣服遮罩；下例不含定位算法）：

```python
from PIL import Image, ImageChops

paint = Image.open("registered-paint.png").convert("RGBA")
mask_image = Image.open("outline.png")
mask = (mask_image if mask_image.mode == "L"
        else mask_image.getchannel("A"))
assert paint.size == mask.size == (939, 1676)
# 两者相乘，保留真实纱/蕾丝透明；绝不把遮罩直接当成成品 alpha。
paint.putalpha(ImageChops.multiply(paint.getchannel("A"), mask))
paint.save("front.png")
Image.new("RGBA", paint.size, (0, 0, 0, 0)).save("back.png")
# 试穿另外保存，不写回衣服文件。
body = Image.open("assets/materials/characters/open-arms/body.png").convert("RGBA")
Image.alpha_composite(body, paint).save("tryon.png")
```

- 归位时在空画布上 `alpha_composite(tile, dest=(x, y))`，不要 `paste(tile, pos, tile)` 后重复乘 alpha，造成边缘透明度被重复削弱。
- 遮罩只限制允许绘图范围，不能凭空补足缺失材质。实布内部应覆盖却透明的地方必须补画；纱面和透孔则保留原本的半透明。
- 不允许 `max(衣服alpha, 人物alpha)`、最近邻取色、膨胀扩边、调和填色、全局羽化、拉长像素、非等比拉伸、TPS 或新自动网格拟合。
- 已保存的用户网格/曲线仍按现有微调流程使用，不能因本 SOP 又套一遍自动变形。衣服材质修补与用户变换分开存储，发布前对比拟合快照，用户有新修改就重新读取合并。

### D. 换色、印花和通用面料的代码边界

- “基础款”标签只是用户分类，不等于换色层已齐全。需要这些功能时交付同坐标的 `base-mask.png`、`shadow.png`、`highlight.png`、`texture.png`、`lineart.png` 与 `material.json`；领边、扣件等固定色区域另用 `trim-mask.png` 保护。
- 真正线稿要在上色前保留；去色彩稿不冒充原线稿。阴影与高光不能烘成不可分的底色，否则深浅色会发灰、糊边。
- 接入现有 `assets/garment-prints/material.js` 的 `M.pixels()`，保留当前实现的源图 alpha；底色按可换色遮罩参与，阴影 multiply，高光 screen，布纹调制 RGB，最后叠线稿。不能另写一套改变几何的面料渲染器。
- 通用格纹/花纹使用独立平铺素材与缩放/偏移参数，裁在衣服允许区域内；不能在衣服外形成矩形背景，也不通过新程序位移去伪造褶皱。现有用户网格随原有流程作用于整件。
- 蕾丝若需要真实透孔，应有独立面料透明覆盖，并和源衣服 alpha 相乘；不能用 RGB 变亮冒充镂空。改变透明覆盖属于新面料能力，应单独实现和验收，不能宣称现有 RGB 布纹调制已支持。
- 面料切换的恒定关系是 `输出alpha ≤ 原衣服alpha`，不能扩衣服边缘、补内片。扣件/固定饰边按保护遮罩保留；纱面不自动添加不透明衬里。
- 每款测试浅色、蓝色、深色及适用面料。普通彩稿仅交付彩稿能力；不能只加一个标签就宣布支持通用换料。

### E. 技术预检、人工验收、实际入库

新增只读预检工具：`tools/validate-clothing-art.py`。它不改图、不补色、不写衣橱，也不自动证明没有内片。`technicalPass` 只代表像素/文件约束通过，`visualPass` 必须由实际检查另行记录。

`outline-record.json` 至少记录批准依据与遮罩文件的 SHA-256。哈希只是追踪证据，不能把身体扩边来源改名洗成服装轮廓：

```json
{
  "basis": "approved-garment-outline",
  "approved": true,
  "bodyAlphaExpanded": false,
  "sha256": "替换为实际 outline.png 的 SHA-256"
}
```

在项目根目录执行（`python` 指安装了 Pillow、numpy 的 Python）：

```powershell
python tools/validate-clothing-art.py --front assets/deliveries/BATCH/ITEM/front.png --back assets/deliveries/BATCH/ITEM/back.png --outline assets/deliveries/BATCH/ITEM/outline.png --outline-record assets/deliveries/BATCH/ITEM/outline-record.json
```

- 检查 PNG 画布、前图非空及透明背景、后图全透明、成品 alpha 不超过批准遮罩、轮廓记录与哈希一致。一个灰度级容差仅用于舍入，不允许几何扩边。
- 可加 `--forbidden forbidden.png`：显式标出领口后缘、袖口内筒等禁止区域；这些区域必须全透明。程序不能自行识别“哪块是内片”，禁止区必须依据本件设计设置。
- 实布可加 `--required-opaque required.png`，只标应有不透明衣料的内部，排除抗锯齿边缘和透孔；默认 alpha 至少 250。纱/蕾丝透明区域不要误放进该遮罩。失败就回去补画，工具没有填充兜底。
- 技术通过后逐件检查浅底、深底、人物全身、100% 双侧肩腋/袖内缘/袖口/领口/腰口；宽袖多看整段袖面，下装加看裆部/胯侧/裙摆，透材加看实际叠穿。
- 保存原图、提示词、轮廓及哈希、等比归位参数、当前母版哈希、预检结果与视觉截图。先完成证据，最后才写导入清单；上面的示例占位路径和占位哈希不能用于发布。
- 新件走 `assets/deliveries/README.txt` 与 `tools/prepare-art-deliveries.py`，归位成品用 `approved-front-only-registered-import`；真正分层的基础款用 `approved-layered-registered-import`。混合批次按现有合同分别提供对应清单，不强行给全部单品标同一种能力。
- 当前导入器校验部分技术字段，但不会自动调用此新增预检，也不会替代人工验收。制作脚本必须先运行预检并检查退出码，失败时不写发布清单；不能只生成一个 JSON 文件就忽略失败。
- Python 批次脚本调用时使用 `subprocess.run([sys.executable, "tools/validate-clothing-art.py", ...实际参数], check=True)`，参数逐项组成列表；`check=True` 失败即抛错，禁止捕获后继续发布。预检通过且人工视觉通过后，再原子写入最终清单；暂存清单不要使用自动发现的 manifest/delivery 文件名。
- 原件返修沿用 ID，走 `REGENERATION.md` 的保护流程；不能用新件导入“跳过已有 ID”的行为冒充替换。不要手工重建 collection 或覆盖用户版型。
- 实际衣橱中核对加载 URL/文件哈希，切换、卸装、刷新后再看一次，确认显示图和验收图一致。需要刷新资源时用现有版本化资源路径，不能只改未参与前端刷新的元数据。
- 2026-10-25：同一路径替换 PNG 后，长期打开的主界面可能仍复用旧图片或原有 DOM。接口现在通过 `wardrobe-asset-versions.cjs` 提供文件版本元数据，运行时图片地址附 `av`，主界面、手机端和 fit editor 使用 `assets/asset-version.js` 处理版本地址。版本由文件时间与大小标识，不是内容哈希；验收仍核对实际响应/已解码图像。原素材路径与用户版型不改。URL 可能有查询参数，本地文件比较先解析 pathname，优先直接检查实际网络响应；不能把带查询参数的 URL 当磁盘路径。

### 每件的最终签收条件

1. 轮廓正确：服装自己的轮廓，固定人物与姿势；贴身有松量，宽袖完整、靠近衣身且连接自然。
2. 结构正确：全部无内片、无后领圈/后腰边/袖裤口空筒；前面真实结构仍保留。
3. 材质正确：无糊边、平色补条、拉长像素；针织/纱/蕾丝/皮革各有实际质感。
4. 数据正确：同画布、透明图、原 ID 及手调保留，换色层按真实完成度登记。
5. 显示正确：真实衣橱文件与通过的交付文件一致；完成全身和 100% 局部检查后才签收。

下面保留项目既有的流程细则、人物沿革与故障溯源；与上文冲突时以上述最新要求为准。

## 当前必须执行的制作顺序（2026-10-24）

1. **确定清单**：检查前端基础款标记、已有款式和用户最新照片；重复版型复用。先记录名称、分类、材质、独立装备关系。腰间系衣/裙片是配饰，包包按用户要求排除。
2. **冻结轮廓**：读取唯一人物母版和该衣服最新手调。锁住服装外轮廓、腋下连接、前襟空隙、袖长及袖口。外套是完整的服装轮廓，不能把人物身体轮廓当成衣片轮廓。已有轮廓未经用户要求不改。
3. **在轮廓内画**：在确认过的衣服轮廓内绘制基色、材质、接缝和自然褶皱。袖子必须与衣身连接，提花/格纹/罗纹应沿完整袖面连续。不能画完一个偏窄的袖子，再按人物皮肤轮廓铺色补宽。
4. **补画真正衣料**：残缺或异常处使用 image_gen 补画，保留原画风和同种面料，周边图案与明暗接上。程序只负责定位、裁切、透明遮罩和合成；禁止邻近取色扩边、颜色扩散/调和填充、模糊色带、拉长边缘像素代替美术。禁止因此生成身体两侧的平直补丁或袖子内侧无纹理长条。
5. **全品类无内片**：所有服装只保留正面实际可见衣料；领口、袖口、裤口、裙腰、开襟和衣摆均不画内片、后缘和里衬。不能把这些多余结构移到 back.png 冒充修好；应删除。back.png 为全透明技术占位。
6. **保留调整**：同件修补不另发重复 ID。只替换被修补的画面，保留用户原有外轮廓、网格、曲线、位置、旋转、缩放、擦除、已存印花和备注。需要映射到已保存版型时，只复用用户已有变换，不发明新的自动变形。发布前发现用户有更新，读取最新状态再合并。
7. **逐件验收**：每件同时看浅底、深底、人物试穿和 100% 局部。局部至少含双侧肩/腋下、完整袖内缘、双袖口、前襟/身体两侧、领口和腰口。左右都检查；有花纹的服装额外看图案是否断带。不得以“全身看不出来”或“alpha 校验通过”代替视觉检查。
8. **实际替换**：先存旧图、原始生成图、提示词、轮廓遮罩和补画范围，再更新同一衣服的源图、当前穿戴图、缩略图及导出包。原件、手调版本与源图都要同步检查，不能只修离线预览。实际衣橱验证切换、卸装与刷新后，再写通过记录。

不通过的情况：腋下断开、袖内侧平色色块、图案到补片处消失、袖口后片露出、身体后方多出衣料、重置手调、把彩稿说成已做好换色层。发现任何一项，继续修正，不让用户接手清理。

### 旧扩边轮廓的溯源检查（2026-10-24）

- “alpha 与上一版相同”不代表轮廓正确。若源目录有 `coverage.json` 且 `completedPixels > 0`，须检查是否曾按人物 alpha 扩边；此类图不能直接作为批准的服装轮廓。
- `sleeve-repaint-v1` 的旧合成方式只更新 RGB，强制保留 `before.png` alpha，曾把扩边后的轮廓一起保留。该方式不能用于修复扩边本身；旧批次已增加拒绝检查，粉色叠搭上衣和彩条针织衫的旧签收已撤回。
- 必须区分生成原稿、等比归位图、后处理图、已保存手调图、前端实际加载图。验收同时检查 PNG 的透明边缘与材质，不能只看生成原稿或缩略图。
- `kg-mockneck-knit-v1`（Afternoon Pause）曾在入库前被偏窄的通用 outline 裁掉约 2.6 万个实布像素：袖口罗纹和身体两侧布量被截断。问题发生在 `paint alpha × outline`，游戏只是显示裁后文件。遮罩来源标为“服装轮廓”也不等于轮廓已与实际设计对齐；裁切前后须并排比较，检查失去的实布、接缝与下摆。不能把 `clippedToFrozenOutline=true` 当视觉通过。见 `sources/afternoon-pause-investigation-v1/`。
- 更新后的 `dressup-single-item/scripts/register_front.py` 会统计裁前/裁后 alpha 覆盖损失，超过 2% 默认阻止生产输出。`--inspect-clipping` 仅输出诊断比较图、被删衣料和报告，不生成 front.png、不签收；有意裁切须实际审阅并绑定原稿、轮廓、归位参数与证据哈希。2% 是排查阈值，不能作为视觉合格线。项目 `tools/validate-clothing-art.py` 只看成品技术约束，不能独自发现此前被误删的布料。
- 排查前端时记录实际图片 URL、图片哈希、手调覆盖来源和 CSS 变换。确认显示文件与交付一致后，问题应回到制作链处理，不靠前端缩放或模糊掩盖。
- 不能仅删除旧扩边然后交付：若因此露出手臂，需按独立确认的服装轮廓重画完整袖片，检查袖身与腋下连贯后再发布。排查记录见 `sources/sleeve-edge-investigation-v1/`。

## 出图与批量节奏

当前母版更新为 `characters/face-calves-refined-v4/` 归档的版本：沿用 v3 半写实哑光肤质，面部更清甜。用户明确授权这一次轻调膝盖以下的小腿和脚尖，去除内八；该次例外不允许后续出衣服时继续改变人物姿势。脸部内部与 y≥1100 的小腿区域以外，像素保持上一版不变，上半身、手臂、腰胯和已有衣服坐标保留。后续鞋袜必须参考当前 `characters/open-arms/body.png` 的新脚尖方向；旧人物和用户服装调整均归档保留，不自动重置修版数据。

1. 按用户清单一次设计多件，分配稳定 ID、名称、槽位。名称尽量不带颜色；同款换色不能充当不同款式。
2. 批量确认服装轮廓 → 在轮廓内绘制 → 初步归位 → 逐件检查关键接缝与材质 → 单品和试穿总览。整体版型可继续手调；断袖、补色块、露后片必须在交付前解决。
3. 精致、偏卡通的半写实二次元画风，明暗清楚，哑光材质。完成度参考麂皮短裙，材质本身仍须符合各件设计；避免塑料感、油亮高光与低对比灰雾。
4. 褶皱由美术画出自然阴影与必要结构线，不生成程序位移、密集条带阴影或随褶皱扭曲的印花。胸前留相对平整的印花区域。
5. 默认单件纯色、真实透明背景；不烘焙印花、人物、皮肤、头发、衣架、文字、水印。试穿合成图另存，不能冒充透明衣服。

## 可见结构和版型

- 2026-10-24 用户最新要求：领口、袖口与半裙的后片全部修掉。此要求优先于通用前后片拆分规则；只交付正面可见衣片，去掉后领内圈、袖口后翻边、后腰边和后片，back.png 仅作全透明占位，不在之后的重建或补全中恢复。保留前领边、前袖口、前腰头与用户已保存的版型。

- 优先画穿着时正面实际可见的衣片。腰头只保留前腰，不露后腰边、内侧或空筒口；袖口也只保留正面可见结构。
- 上衣肩点、腋下和袖子角度对照张臂母版，给手臂与身体之间留准空隙。不要照搬垂手人物的袖子角度。
- 所有款式的 back.png 均为全透明技术占位。不为了文件格式、立体感或自动补全添加内片和后领等结构。
- 原始出图完整归档。初步归位只用等比缩放和平移，已有同画布归位的分层直接保留；禁止非等比拉伸、TPS、自动网格变形来强行贴身。
- 不自动覆盖用户手调的网格、曲线、位置、尺寸。细节不合格如实记录并在交付前解决，不能把断袖、糊边、内片等制作缺陷留给用户微调清理。
- 用户手调可在“移动 / 缩放”勾选“自由比例”，或按住 Ctrl 拉角点，独立改变宽高；Alt 可围绕中心缩放。此能力只用于用户主动修版，自动入库仍保持原始比例，不替用户强行拉伸。
- 新衣服无须预置 openings 才能微调：所有单品都可从“领口 / 腰口 → ＋开口”手动添加，保存后随该件草稿重新载入。没有新增开口时保留已验收的正面结构与透明 back 占位，不为显示工具自动补后片或改分层。

## 换色与布料分层

- 保留真正先完成的线稿，禁止将最终彩稿去色后冒充原线稿。
- 需要换色换布料的基础款保留 lineart、base-mask、trim-mask、shadow、highlight、texture。各层使用同一 939×1676 坐标与轮廓。
- 底色按遮罩填色；布纹独立裁切；绘制阴影 multiply、高光 screen、线稿叠加。换布料不能移动轮廓、改变人物或引入程序褶皱。
- 同一款至少看浅色、蓝色、深色；棉料按已制作的精梳、竹节、水洗等预设检查。未分离的彩色图只能标记为彩稿，不能宣称可改色生产层已完成。
- 内搭是单独的可选素材，不重画人物来适应每件衣服，也不把内搭、皮肤和身体合成进衣服。露肩款注意母版肩带或内搭露出，将实际问题写入 QA。

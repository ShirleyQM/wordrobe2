# 词间衣橱

蓝色系换装背单词游戏原型。沈知微为默认人物，使用 939 × 1676 固定坐标分层；长裙、短裙、连衣裙各 5 款，搭配上衣、袜子、鞋、包与首饰。

## 运行

需要 Node.js 18 或以上。页面运行无第三方依赖。

```sh
npm start
```

打开 http://127.0.0.1:4173/ 。印花编辑器位于 /assets/print-studio/index.html ，裙装验收预览位于 /assets/skirt-collection-v1/index.html 。存档保存在浏览器本地，换电脑或浏览器不会自动同步。

## 学习与换装

- 每组逐张学习 10 个 GRE 单词，配中文释义与例句翻译；汇总后随机 5 题。
- 完成一组立即到账 10 积分，可继续下一组。每累计学习 30 词，必须先完成进阶挑战，首次答对至少 8/10 题才能继续积分。
- 积分解锁单品，连衣裙与上下装互斥。替换美术时迁移已有单品，保留积分与学习进度。
- 商品展示图与穿戴图分开：人物按后发 → 衣物后片 → 身体 → 衣物前片 → 手部与配饰 → 前发合成。腰头、后领与袖口内侧不能盖住身体。
- 本批裙装为彩色穿戴层，尚未拆成可分区改色的线稿、基色、阴影层。

## 印花 T 恤编辑器

三种 SVG 基础版型共用双臂略展开的 V2 母版，支持换色、9 种图案、拖动、等比缩放、Ctrl 自由拉伸、布纹与二维褶皱。

进入“修版型”可拖动蓝色轮廓点、调整橙色曲率手柄；点击“添加节点”后点轮廓，或双击轮廓加点。默认左右对称，支持撤销、重做、按款自动保存、还原与导出 JSON。加点保留原始贝塞尔曲线。版型导出目前尚无导入界面。

修改根目录 print.html、print.css、print.js、print-transform.js、print-garment.js、print-fabric.js 后执行 `node prepare-print.cjs`，更新 /assets/print-studio/ 的预览文件。图案原文件和已裁切的透明 PNG 分别位于 assets/print-sources/ 与 assets/prints/。

## 测试与打包

```sh
npm test

```

测试覆盖学习积分、30 词关卡、换装互斥、图案变换、轮廓加点、曲线保持与对称编辑。`npm run test:assets` 额外校验 15 款穿戴层，需要 sharp；可将 DRESSUP_NODE_MODULES 指向已有的 Node 依赖目录。

素材压缩包由 package-assets.cjs 使用 Node 内置模块重建，输出 assets/skirt-collection-v1/collection.zip 与 assets/gentle-campus-v2/shen-zhiwei-assets.zip。ZIP 文件不纳入 Git，全部源图、图层与校验记录均保留；克隆后先执行打包命令即可恢复页面下载。

## 美术制作 Skill

skills/dressup-single-item/ 包含 SOP、母版坐标、单件归位、穿戴前后遮挡和逐件验收脚本。可复制到自己的技能目录使用。各款的 item.json、qa.json、wearable-qa.json 记录来源、变换、遮罩与文件哈希；换母版必须重新归位和验收。

## GRE 测试数据

`gre-data.js` 包含下载文件夹《【词表】再要你命3000（第2版）大字版+v1.0.xlsx》中抽取的 30 词，保留原始释义、工作表和行号。展示释义按当前词义精简；配套例句、首字母填空和词义匹配为原创练习。相近词义的单词避免互作自动匹配题干扰项。

另选取 5 道单空选择原题：`GRE填空机经1100题难度分级版（第二版）+(1).pdf` 第 7 页第 1、2 题、第 9 页第 1 题，以及《填空1000题.pdf》第 4 页 10102005、第 5 页 10102014。原题保留原有选项，随机排列展示顺序。仅规范空格与连字字符；答案按句意人工核对，所读页面未附显式答案键。题目记录中保留来源、页码、题号和简短解析。当前没有混入需要选两个答案或多空作答的题目。

每组小测含 1 道语境单选、1 道中译选择、1 道英文匹配和 2 道首字母填空；学过词中存在所选 PDF 原题时优先抽一道原题，否则使用配套例句。首字母填空可输入剩余字母或完整单词，不区分大小写。进阶仍为 10 题、首次答对至少 8 题通过，并混入语境选择、首字母填空和完整拼写。

运行 `npm test` 验证核心规则。测试使用隔离内存状态，不修改浏览器存档。


## 当前范围

这是本地原型，尚未完成小红书 MiniTool 上传兼容验收，也未接入云账号、发音和云存档。素材及 GRE 样本用于本项目原型测试；来源和题号保存在数据文件中。


主界面素材工作流

在同一个主界面切换“衣橱 / 印花 / 修版型”。学院风四件和三款 T 恤直接进入衣橱，“调整这件”打开对应编辑器。旧人物衣服保留在原人物画布，新版素材使用双臂展开的温柔母版，切换时恢复各自穿搭。

编辑后约 400ms 自动保存草稿并生成 939×1676 的透明前后片。出现“已更新到衣橱”即已写入 assets/live-wardrobe/；衣橱按单品 ID 获取当前版本，刷新、重开页面或重启本地服务都载入最新记录。原图和既往生成版本保留。编辑入口共用原来的曲线工具。

保存接口由 server.cjs / wardrobe-store.cjs 提供，两个编辑器共用 assets/wardrobe-library.js。并发旧页面不能覆盖新修订；未能保存时面板明确显示错误。本地未提交调整会保留；若服务端已有更高修订，加载最新版并在浏览器 wardrobe-recovery-* 中备份冲突草稿。部署时须连同可写素材存储和保存接口一起迁移；目前运行于本地服务。

验证：node test-wardrobe-library.cjs（保存、重载、冲突、坏图拒绝、来源检查、历史版本）。


调衣模式与独立印花

当前主界面为 ART_MODE：全部单品直接试穿，隐藏学习、积分和解锁入口，已有学习数据保留。名称在展示时移除可变的颜色词，稳定单品 ID 不变。

“加印花”和“印花”统一使用 assets/garment-prints/，按单品 ID 分开保存图案、位置和尺寸。印花是单独透明图层，按衣服最新前片透明度裁切；不写入衣服底图。T 恤底图发布不再混入当前全局印花，避免三款相互串图。已有旧版图案只迁移到当时选中的一款 T 恤，其余两款回归各自纯色底图。

保存组 imprints 与 preppy / prints 独立修订；主界面将对应印花绘制在所属衣服上方，并被随后绘制的其他衣服自然遮挡。修改底图时会重新按最新版轮廓裁切。T 恤修版入口仍复用旧曲线工具，独立印花入口兼容原 /assets/print-studio/ 书签。


全衣橱修版同步

主界面的“修版型”和“调整这件”共用原有 Atelier / PrintGarment 曲线编辑器，以 universal=1 加载 assets/fit-catalog/collection.json 中与衣橱对应的 30 件单品。分类、顺序和当前选中项同步，修版面板切换单品会同步衣橱当前穿戴。所有来源沿用各自人物母版，不混用站姿。

fit-catalog 保存本次接入时的透明原始前后片与轮廓锚点，sourceSha256 用来确认后续编辑没有覆盖源图。fittings 保存组按单品 ID 记录调整、最新透明前后片和缩略图；衣橱和印花优先解析此组，保证刷新后使用最新修版。只有实际改动过的单品参与发布，不会在进入面板时覆盖其他衣服。旧 preppy / prints 调整及原始图片继续保留。


新增素材接入

美术工作树中已完成的 34 件切图由 import-new-materials.py 导入 assets/new-materials/ 和 fit-catalog/。服务器通过 materials 清单提供给衣橱、修版及印花，现有 30 件加新增 34 件共 64 件。新增衣服仅初步归位，标记“待微调”，尚未宣称通过精确试穿验收；导入不会覆盖原有来源或用户 fittings 记录。修版采用增量发布，避免每次重新上传其他已经修好的衣服。

印花面板动态读取 extracted-motifs-v1/manifest.json：207 张新增透明图案，加原来的 9 张，共 216 张。按类别和每页 12 张浏览，图案仍按服装 ID 独立保存。进行中的半写实风格重绘不自动覆盖已修衣服。


统一素材目录

当前素材入口为 [assets/materials](assets/materials/README.md)：garments（衣服编辑源）、patterns（207 新图案与 9 原图案）、characters（人物）、published（自动保存的可用版本）、sources（导入原稿）。参考其中 catalog.json。旧工作目录保留为进行中的生成工作区或历史档案；旧 URL 由 asset-paths.cjs 兼容，新的保存统一写入 materials/published。

重新生成：修版面板右上角的按钮会停用单件、保存快照，交给专用 Codex 会话重画。失败可重试或恢复旧版；新稿通过验收才恢复可用。流程见 REGENERATION.md。手调版本优先，生成期间出现新手调记录时拒绝自动覆盖。

# 固定人物单件服装

从批准的母版、服装轮廓和设计参考制作可独立穿脱的服装。批量是逐件完成闭环，不是生成服装九宫格。

## 先读约束

- 先读工作项目的 `AGENTS.md`、最新生产 SOP 和用户要求。在“换装背单词游戏”项目读取 `assets/materials/PRODUCTION_SOP.md`；当前规则摘要及接入点见 [references/project-integration.md](references/project-integration.md)。其他项目不能照搬此人物、坐标、槽位或发布路径。
- 本用户的默认制作方式：所有服装只画正面可见衣料，**都不画内片**。无后领圈、后腰边、袖裤口内筒/后翻片、里衬、衣摆背面、开襟背部连接片；`back.png` 全透明占位。独立内搭另做一件；不把多余结构藏进 back 层。
- 冻结人物、姿势和已批准的服装轮廓。外套轮廓是衣服自己的轮廓；禁止从人物 alpha 扩衣服。缺布用内置 image_gen 补真实材质，不能用邻近取色、扩散填色、纯色长条、拉长像素、全局模糊或新自动变形填缝。
- 裁切前后必须并排看真实布面：轮廓记录写 approved 也不代表与设计匹配。不得为套通用轮廓截掉袖口罗纹、身体两侧布量、褶皱和下摆。先确定是定位错误、临时轮廓错误，还是绘图超出用户锁定轮廓；分别修定位/轮廓或重新绘图，不能盲目扩大遮罩。
- 修原件沿用 ID，归档旧图，保留最新用户网格、曲线、移动缩放、擦除、印花与备注。生成脚本不直接覆盖衣橱、拟合数据或正式文件。

## 每件闭环

1. **规格与去重**：查当前库存与基础款标记，记录稳定 ID、槽位、版型、袖型、面料及独立装备关系。同款不同色复用；腰间系衣/叠裙配件化，本项目不做包。
2. **锁轮廓**：按类别锚点确定肩/腋/胸/腰/胯/袖口等，保留最新手调。输出衣服自己的遮罩和可追溯批准记录；旧身体扩边 alpha 不能当批准轮廓。
3. **出图/补画**：使用 image_gen，单件真实透明背景，无人体、皮肤、衣架、品牌文字。在服装轮廓内画结构和完整材质；宽袖先定全袖面再画。保存实际提示词、参考、原稿及修稿。
4. **归位**：新素材只做明确的等比缩放和平移；已有同画布图不再自动拟合。用 `scripts/register_front.py` 输出独立候选包，保留实际绘图 alpha 并裁在批准轮廓内，不填充缺布。默认拦住未审阅的大面积裁切；可用 `--inspect-clipping` 只输出裁切前后与被删衣料证据，先解决误裁再生产。用 `scripts/validate_front.py` 单独复检已归位图。
5. **视觉验收**：全身试穿、浅/深底、100% 双侧腋下、袖内缘、袖口、领口、腰口；下装再看胯/裆/裙摆，纱与蕾丝看真实透孔。程序不能识别所有内片，技术通过不能代替这一步。
6. **能力登记**：彩稿、已归位穿戴图、真正可改色/换料的分层资产分别登记。独立线稿必须在上色前保存；不能去色彩稿冒充线稿。
7. **发布验证**：按当前项目合同走导入/受保护返修，最后写清单。实际衣橱核对 URL/哈希与当前手调，试切换、卸装、刷新，再签收。未完成项不计入已替换。

脚本只做确定性归位/裁切/合成/预检；不出图、不签视觉通过、不写正式库、不自动选择轮廓或变换。Python 依赖 Pillow、numpy，使用已配置运行时，不修改运行时安装目录。

旧 `register.cjs` 的分段宽度拉伸与自动拟合已停用。旧 accept/validate-batch 仅供核对历史 Node 批次，不可用于新 Python 包或标记其视觉通过。
